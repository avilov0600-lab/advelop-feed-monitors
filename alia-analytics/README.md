# ALIA — отдельная аналитика на 11:30 МСК

Компонент запускается независимо от мониторинга фидов. Служба `alia-analytics.service`,
таймер `alia-analytics.timer`, данные `/var/lib/alia-analytics`.
Существующий мониторинг 09:00 / 13:00 / 15:30 / 18:30, база подписчиков и последний
обычный отчёт для `/start` не изменяются.

## Источники и границы

- Циан: полный список опубликованных XML-объявлений, аукцион по этим ID.
  Текущая ставка, ставка лидера, страница и позиция — срез аукциона лотов,
  не CPL-ставка ЖК и не гарантированная позиция для любого поискового запроса.
- Показы и просмотры Циан за вчера: готовый кэш утреннего мониторинга читается
  без изменений. Если его нет, выполняется сбор с бюджетом времени 100 секунд.
  Неполная статистика не суммируется в полный итог. Выборка — опубликованные
  объявления на момент сбора, а не все исторические объявления кабинета.
- Авито: `stats/v2/accounts/{id}/items`, группировка `day`, метрики
  `impressions`, `views`, `contacts`, весь аккаунт ALIA. Даты и полнота проверяются.
  Контакты не называются звонками/платными звонками. Метод не возвращает позиции.
- ДБ: только раздел «Базы недвижимости» вкладки отчётного месяца.
  Колонки находятся по полным заголовкам, строки других каналов исключаются.
  Дата формулы «Вчера» должна совпасть с отчётной. Пустые значения не равны нулю.
- Журнал «Базы — журнал действий»: даты подтверждения заполнения звонков/расхода,
  дата и месяц согласованного плана, последние действия за 7 дней.
  Предложенные действия не выдаются за выполненные. Причинность не выдумывается.

Определения и ограничения: расходы из ДБ сохраняют её налоговую/агентскую базу;
оплаченные звонки и API-списания ещё не сведены с квалифицированными звонками.
Конверсия платных в целевые без сопоставленных звонков не рассчитывается.
Свежая квалификация предварительная и перечитывается каждый день.
Сейчас выгружается текущий отчётный месяц, исторические месяцы не пересчитываются.

## Доступ к ДБ

02.11.2026 пользователь разрешил серверу чтение по уже существующему доступу
«Anyone with the link». Права таблицы не менялись. Google Visualization CSV
читается только по диапазонам: дата D6:E6, заголовки A10:BL10, блок A15:BL23
ноябрьской вкладки; A2:J2 и A5:J205 журнала. Другие каналы не скачиваются.
Пять ограниченных запросов в день. `headers=0` сохраняет первую строку диапазона;
локализованные числа преобразуются, прочерки остаются отсутствием данных.
Перед декабрём необходимо добавить проверенный gid и диапазоны новой вкладки
в `PUBLIC_MONTHS`. Неизвестный месяц вызывает явный статус отсутствия данных.
Параметры диапазона документированы Google:
https://developers.google.com/chart/interactive/docs/spreadsheets#query-source-ranges

Альтернатива, если клиент закроет просмотр по ссылке: отдельный Google service
account с ролью «Читатель» только в этой таблице.
JSON-ключ вне репозитория: `/etc/alia-analytics-google.json`, владелец root, 0600.
OAuth scope `spreadsheets.readonly`. Не открывать таблицу публично.
Без ключа используется разрешённый CSV-доступ. Если он недоступен, отчёт явно
сообщает об ошибке ДБ, а не показывает фиктивные нули.
Ключи Cian/Avito/Telegram читаются из существующего `/etc/asterus-feed-monitor.env`.

## Установка и проверка

1. Проверить исходники, затем `sh install.sh` от root в каталоге компонента.
2. `.../.venv/bin/python /opt/alia-analytics/run.py` — сбор и текст без рассылки.
3. `.../.venv/bin/python /opt/alia-analytics/run.py --send --owner-only --owner-chat-id <ID>` — владельцу.
   ID должен быть проверенным активным подписчиком этого бота; произвольный первый
   подписчик никогда не выбирается. Нужный ID не хранится в исходниках.
4. `systemctl enable --now alia-analytics.timer` после проверки результата.
5. `systemctl list-timers alia-analytics.timer developer-feed-monitor@asterus.timer`.

`python3 -m unittest discover -s alia-analytics -v` запускает проверки из корня repo.
`--refresh` обновляет данные, но не повторяет уже доставленный дневной отчёт.
Предпросмотр не кеширует будущий плановый запуск на 11:30.
Рассылка идёт активным подписчикам `tenant=asterus`; `/stop` проверяется перед отправкой.
Известный успешный результат не отправляется повторно. Неоднозначный сетевой
таймаут сохраняется как `unknown` для ручной сверки, чтобы не дублировать сообщение.
Транспорт Telegram общий с рабочими ботами; он может повторить сетевой запрос при
переключении семейства IP — абсолютная гарантия exactly-once Telegram не предоставляется.

Отключение: `systemctl disable --now alia-analytics.timer`. Другие службы не затрагиваются.

Официальный контракт Циан: https://public-api.cian.ru/swagger/latest
Схема Авито stats/v2 проверена ответом аккаунта ALIA 02.11.2026.

## Диагностика ставок и CPL, 02.11.2026

Существующий ключ ALIA успешно получает опубликованные объявления, показы,
страницу/позицию и `leaderBet`. Поле `currentBet` в проверенных ответах отсутствует.
Отсутствие поля не превращается в ставку 0 или в вывод «ставка не менялась».

Прямые проверки на сервере: `/v1/get-operations` и `/v2/get-calls-report`
вернули пустые списки за 01.11.2026 и за весь октябрь. `/v1/get-agents`
вернул 0 сотрудников; `/v1/get-offer-active-services` для трёх объявлений — пусто.
Это не доказывает нулевой расход/число CPL-звонков. Вызовы сделаны обычному API;
в его текущем контракте нет признака платности звонка и ставки CPL-ЖК.
Телефоны, записи разговоров и ключи не сохранялись в диагностических результатах.

Циан отдельно описывает API новостроек со стоимостью/типом звонка и текущей
ставкой аукциона звонков:
https://www.cian.ru/stati-api-po-novostrojkam-novye-vozmozhnosti-dlja-zastrojschikov-314144/
Статья 2021 года подтверждает различие продуктов, но не заменяет актуальный
контракт и проверку доступа. Для завершения интеграции нужны документация методов
API новостроек и подтверждение их доступности для существующего ключа ALIA.
Не подбирать скрытые методы и не использовать API смены ставок.

Что запросить у менеджера Циан: read-only методы текущей CPL-ставки/позиций ЖК,
оплаченных звонков и начислений/возвратов по ALIA; правила дат, пагинации,
идентификатор ЖК, единицы денег и НДС; работает ли имеющийся ключ или нужен иной
доступ. Секреты не пересылать в публичные issues/репозиторий.

Правила будущей сверки:
- ДБ содержит накопительный факт с начала месяца по вчера, а не только вчерашний день.
- Сравнивать одинаковые ЖК, площадку, период и денежную базу (НДС/комиссия/бонусы).
- Пользователь подтвердил 02.11.2026: ДБ содержит всю сумму из ЛК с НДС,
  без отдельной агентской комиссии; в ЛК сумма тоже с НДС (коэффициент 1,22).
  Обе суммы с НДС сравнивать напрямую, не умножать повторно. Если конкретный
  API-метод возвращает сумму без НДС, сначала подтвердить это его контрактом.
- Целевые в ДБ определяются критериями клиента, а не признаком оплаты площадке.
  Принадлежность всех целевых к оплаченной выборке пока не подтверждена.
- Оплаченные обращения брать по явному признаку биллинга, учитывать возвраты;
  успешный звонок и контакт Авито не являются доказательством оплаты.
- Конверсия = целевые из оплаченного набора / оплаченные звонки × 100%.
  Если в ДБ есть целевые бесплатные обращения, нужен отдельный числитель.
- При отсутствующем/нулевом знаменателе или неполных данных процент не показывать.
  При несовпадении периода или целевых больше оплаченных сообщать о несопоставимости.
- Перечитывать разметку ежедневно; последние дни предварительные. Подтверждение
  заполнения ДБ не равно окончательной квалификации каждого звонка.

Расход и платные звонки CPL ещё НЕ подключены. Отчёт явно показывает это ограничение.
