# Мониторинг новых застройщиков ADVelop

Общий движок с изолированными настройками, состоянием и подписчиками на Timeweb.
Рабочие MASTERS, IKON и DAR используют прежние приложения и не изменяются.

## Источники и границы проверки

`clients.json` содержит источники из анкеты клиента. Фиды ALIA исправлены по
отдельной таблице «Фиды», строки 155–173: используются жилые XML `alya`,
коммерческие `alia_com` не включены. Малые XML ALIA и Кутузов Сити проверяются
как подмножества эталона; отсутствие в них всего основного ассортимента не ошибка.

ALIA: в анкете вместо материнского фида указана главная сайта. Материнский
источник помечается недоступным; совпадение агентских XML не выдаётся за сверку
с клиентом. Каталог `/flats/` даёт отдельный вторичный счётчик квартир.
Для других сайтов отдельные достоверные счётчики пока не подключены; это
явно отмечено в сообщении, посещение главной страницы не заменяет число лотов.

Родина и Дом Дау: нативный Profitbase XML. Эталон — квартиры со статусом
`AVAILABLE`, брони, проданные и недоступные исключаются и отражаются в JSON.
Плато: материнский XML формата Циан. Родина и Плато не размещаются на Авито;
для них Авито отсутствует в запросах, настройках аккаунтов и отчётах.

Астон: Macro JSON содержит квартиры, коммерцию, кладовые, парковки и посторонние
ЖК. Отбор выполняется по `category=flat` и зафиксированным `parent_id` каждого
проекта. Общий JSON Екатеринбурга скачивается один раз за запуск. В рекламе
ожидаются опубликованные, непроданные и незабронированные квартиры. Используется
площадь БТИ, когда заполнена; `estate_studia=1` при двух комнатах означает
европланировку и не обнуляет комнатность. В Циане три разных кабинета, в Авито
один общий: они опрашиваются отдельно, без повторных запросов одного кабинета
для каждого ЖК.

Проверяются ID, дубликаты, состав, площадь, комнаты, этаж, этажность, номер
квартиры и тип сделки. Цены проверяются между рекламными XML. Даты окончания
акций и устаревшие упоминания месяцев выделяются красным. Семантическая
проверка всех рекламных обещаний не выполняется.

Циан API — опубликованные объявления и ошибки импорта. Авито API — активные
уникальные ID с ограниченной пагинацией и паузой 2,6 секунды. Счётчик относится
ко всему кабинету; в отчёте это подписано. Это не пообъектная проверка
фактической публикации каждого ЖК. При ошибках API число не подменяется нулём.
Доступность полного обхода Авито опирается на пять последовательных пустых
страниц; нестабильность самого API требует отдельной диагностики.

Карточки Яндекса читаются как дополнительный источник. Непрочитанное число
остаётся непроверенным. Домклик использует согласованный прокси по XML:
«по фиду; совпадает с остальными XML». Фактическая публикация этим не доказана.
Карточки М2 пока не дают независимого подтверждённого счётчика.

## Развёртывание

Код: `/opt/developer-feed-monitor` на существующем Timeweb VPS. Для каждого
`tenant` отдельные пользователь `tenant-monitor`, окружение
`/etc/tenant-feed-monitor.env` (root, 0600), состояние
`/var/lib/tenant-feed-monitor` (0700), SQLite подписчиков внутри него.
Ключей и токенов в репозитории нет. Общая база подписчиков между клиентами
не используется. Дополнительный публичный HTTP relay не требуется.

`developer-feed-monitor@tenant.timer`: 09:00, 13:00, 15:30, 18:30,
`Europe/Moscow`, ежедневно. `Persistent=true` догоняет пропущенный запуск
после перезагрузки. Параллельный запуск одной systemd-службы невозможен.
Таймаут запуска 15 минут, три попытки скачивания фидов с паузой 2 секунды.
Таймаут одной сетевой операции для материнских CRM-выгрузок — 60 секунд;
для статических XML агентства — 10 секунд. CRM может формировать экспорт
на лету: в первом запуске Macro Астона не уложился в прежние 10 секунд.
Держатся только последние файлы и отчёт, без растущих архивов.

`developer-telegram-poller@tenant.service`: постоянный исходящий long polling
через IPv6, автоматический перезапуск. `/start` подписывает каждого нового
пользователя и отправляет сохранённый отчёт без опроса фидов/API; `/stop`
отключает его. Каждый плановый отчёт отправляется всем активным подписчикам.
До первой подписки отчёт сохраняется без ложной ошибки доставки.
Для временных сетевых ошибок Telegram предусмотрены три попытки отправки
с паузой 2 секунды; заблокировавший бота пользователь не ретраится.
`deploy/resend_latest.py` повторяет доставку сохранённого отчёта без повторных
запросов сайтов, XML и API площадок. При сетевом таймауте Telegram потенциально
возможен дубль сообщения: гарантии exactly-once у отправки нет.

## Верификация

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`
проверяет фильтры материнских источников, ограничения аккаунтов, изоляцию
подписок и сохранённый отчёт для нового пользователя. `deploy/audit_cache.py`
проводит read-only сверку источников; ключи не выводит.

`deploy/provision.py --prepare` готовит директории и systemd-шаблоны без
запуска рассылок. После безопасного подключения токенов `provision.py`
принимает защищённый JSON окружений и включает службы нужных клиентов.

## Состояние подключения на 13 октября 2026

Asterus, Родина, Плато и Астон подключены на Timeweb. Имена всех четырёх
ботов подтверждены через `getMe`, описания и команды установлены. Службы
опроса команд и четыре таймера включены, секреты хранятся в root-only
окружениях 0600. Временные локальные файлы и серверный пакет переноса
удалены после подключения. Первый отчёт каждого бота сохранён в отдельной
SQLite, `/start` проверен из Telegram; в каждом реестре есть активная подписка.
Красный статус отчётов означает найденные расхождения либо неполные источники,
а не сбой планировщика. `deploy/status.py` безопасно показывает состояние
отчётов и число подписок без токенов и идентификаторов чатов.
Материнские источники всех четырёх ЖК Астона успешно загрузились после
увеличения таймаута; отчёт от 13.10.2026 00:46:42 МСК доставлен подписчикам.
