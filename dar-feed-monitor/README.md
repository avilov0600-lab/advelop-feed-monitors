# DAR — контроль выгрузок

Изолированный монитор двух проектов из строк 4–5 анкеты клиента: Дом на Часовой
и Ракурс. Только жилая недвижимость. Оформление Telegram — как IKON: жирные
заголовки, пустые строки между проектами, отдельные блоки XML, площадок и API.

## Источники и проверки

- Ракурс: материнский JSON клиента из анкеты, ЖК 1316 в Planeta.
- Дом на Часовой: в анкете вместо XML указана главная сайта. В каталоге сайта
  обнаружены Planeta project 816 / house 1189 / ЖК 1318; подключён клиентский
  exchange JSON с теми же ID квартир. Это производный источник из каталога,
  а не отдельный независимо предоставленный материнский фид.
- В эталон рекламы входят только `free`; `reserved` показаны отдельным числом.
  Это соответствует доступности, а не означает, что брони считаются проданными.
- Четыре XML Дома на Часовой, пять XML Ракурса. Сопоставление по внешнему ID:
  состав, повторы ID, площадь, комнаты, этаж, этажность, номер квартиры, сделка.
- У Ракурса номер `К3-7` нормализуется в `7`, связь остаётся по уникальному ID.
  Циан `FlatRoomsCount=9` нормализуется как студия, согласно документации Циан.
- Цены сравниваются между рекламными XML; сырая цена клиента не используется
  как обязательный эталон рекламных скидок. Проверяются даты и месяцы акций,
  но не обещается автоматическая проверка смысла всех рекламных утверждений.
- Циан API: опубликованные объявления и ошибки импорта. Авито API: активные
  объявления. Общий кабинет сравнивается с суммой двух XML по площадке;
  это контроль численности кабинета, не пообъектная API-сверка каждого ЖК.
- Карточки Циан/Яндекса: дополнительная попытка прочитать число объявлений.
  Блокировка или отсутствие счётчика явно отмечаются как непроверенные данные.
  Авито контролируется API. Домклик — прокси по XML: равенство количества с
  остальными фидами не выдаётся за доказательство фактической публикации.
- Отдельного независимого счётчика сайта в этой версии нет: для Часовой
  клиентский каталог используется как эталон; сайт не изображается независимой
  четвёртой успешно проверенной системой.

## Runtime

Timeweb VPS: приложение `/opt/dar-feed-monitor`, состояние
`/var/lib/dar-feed-monitor`, отдельная SQLite подписчиков
`/var/lib/dar-telegram-relay/relay.sqlite3`. Никакой общей базы с IKON/MASTERS.
Секреты только в root-only `/etc/dar-feed-monitor.env` и
`/etc/dar-telegram-relay.env`; в исходниках и отчётах их нет.

`dar-feed-monitor.timer`: **09:00, 13:00, 15:30, 18:30 МСК**, каждый день.
Монитор — oneshot; параллельно один экземпляр службы. Таймаут 8 минут.
Отправка Telegram закреплена за IPv6 (`TELEGRAM_IP_FAMILY=ipv6`):
12 октября прямой IPv4 к Telegram с VPS давал таймауты. Это не меняет
маршрутизацию клиентских источников и API Циан/Авито.
Три попытки сетевых скачиваний, пауза 2 секунды. Ошибка источника не становится
нулём и не мешает проверке остальных. Хранятся только последние данные/отчёт,
без растущих архивов. DAR не запускается через GitHub Actions или Yandex Cloud.

`dar-telegram-relay.service`: постоянный реестр с автоматическим рестартом.
Публичный путь `/dar-telegram/`, внутренний порт 8766. Последний сегмент URL
секретный и исключён из access log nginx. Входящие команды принимает отдельная
`dar-telegram-poller.service`: исходящий long polling `getUpdates`, ожидание
до 25 секунд. Входящий webhook Telegram отключён из-за таймаутов доступа к VPS.
Это частота ожидания команд, а не частота проверок XML/API: монитор по-прежнему
запускается только 4 раза в сутки. `/start` сохраняет каждого пользователя и возвращает последний
отчёт без запросов к XML/API. `/stop` отключает рассылку. Каждый плановый отчёт
отправляется всем активным подписчикам, даже если ошибки не изменились.
До первого `/start` отчёт сохраняется без ложной ошибки отправки.

## Проверка и обслуживание

`python3 -m unittest discover -s tests -v` — тесты парсера, изоляции и подписок.
`systemctl list-timers dar-feed-monitor.timer` — следующая проверка.
`systemctl start dar-feed-monitor.service` — внеплановый запуск с рассылкой.
`journalctl -u dar-feed-monitor.service` — технические логи и дайджест.
Первый live-запуск: 12.10.2026, успешно. GitHub API из монитора не вызывается.
